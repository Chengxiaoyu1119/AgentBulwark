## 先给结论

这个比赛不是单纯写论文，也不是只做一个网页演示。它更像“信息安全方向的作品工程赛”：要围绕一个安全问题，做出可运行的原创作品，并能在初赛材料和决赛答辩里证明它有创新性、技术先进性、应用前景、设计完整性和规范文档。

如果从空项目开始，优先建议选择 **方向一：面向大模型及其应用的安全性研究**，备选 **方向八：基于大语言模型的应用安全审计技术** 或 **方向九：APT 供应链攻击检测与溯源系统**。原因很直接：这些方向不依赖无人机、卫星链路、硬件采集卡这类设备，能用软件系统、公开样例、可控攻击脚本和可量化评测做出完整闭环，更适合短周期冲奖。

拿奖高的作品通常不是“有一个想法”，而是能讲清楚并演示这条链路：

> 真实安全痛点 -> 攻击或风险复现 -> 防护/检测原型 -> 数据集或测试用例 -> 指标评估 -> 可视化演示 -> 规范报告与答辩。

## 比赛在做什么

本届比赛目标是选拔和推荐网络空间安全人才，强调创新意识、团队合作、网络安全技术水平、创新实践能力和综合设计能力。作品要围绕信息安全技术与应用设计，既要有技术含量，也要能落地演示。

比赛分为两个赛道：

| 赛道 | 含义 | 适合情况 |
|---|---|---|
| 自由作品赛 | 自主命题、自主设计，作品可以是软件或硬件 | 已有成熟想法、已有项目基础、想做开放选题 |
| 命题挑战赛 | 从组委会发布的安全挑战中选择一个命题，自主设计作品 | 目前空项目、希望贴合官方方向、减少选题跑偏风险 |

当前项目建议走 **命题挑战赛**，因为题目边界清楚，评委更容易按官方成果要求判断完成度。

## 提交与评审

提交材料包括作品文档资料和可执行程序。文档资料为 PDF，大小不超过 10MB，至少包括：

| 材料 | 作用 |
|---|---|
| 作品报告 | 说明问题背景、技术方案、系统设计、创新点、实验结果和应用价值 |
| 作品原创性声明 | 说明作品由团队原创完成，避免知识产权和违规问题 |
| 可执行程序 | 证明不是纸面方案，而是能运行、能演示、能测试的作品 |

初赛采用网络评审，每件作品至少由 3 位专家审阅。评审关注点包括：

| 评审项 | 对作品的实际要求 |
|---|---|
| 创新性 | 不是简单套壳或普通工具拼接，要有明确新方法、新机制或新场景价值 |
| 技术先进性 | 要体现当前安全技术趋势，例如大模型安全、供应链安全、隐私计算、低空安全等 |
| 应用前景 | 作品最好能对应真实行业问题，而不是只在玩具样例上成立 |
| 设计完整性 | 要有完整架构、模块、流程、测试、异常处理和展示闭环 |
| 文档规范性 | 报告结构清楚、图表完整、指标可信、引用和原创说明规范 |

决赛需要现场带作品、文档和设备进行演示答辩，整体约 30 分钟，包含 PPT 陈述、作品演示、测试和专家提问。现场真实环境演示会更有说服力，专家可能检查源代码。

## 9 个命题方向

说明：本项目只选择方向 1「面向大模型及其应用的安全性研究」。下表其余方向仅用于理解比赛命题范围，不作为本项目实现方向；尤其方向 6 的海量日志异常识别不是本项目主题。

| 编号 | 方向 | 要做什么 | 预期成果 |
|---|---|---|---|
| 1 | 面向大模型及其应用的安全性研究 | 从红队视角研究提示注入、模型越狱、训练数据泄露、工具调用劫持、记忆中毒等风险，并做行为监督机制 | 风险分析报告、至少 3 类攻击场景、对抗样本/越狱用例/智能体攻击脚本、行为监督原型、实时告警或阻断展示 |
| 2 | 低空无人机网络安全检测与防护 | 研究无人机与地面站之间的飞控链路、遥测数据、固件更新等风险 | 攻击复现脚本、链路异常检测模块、地面站防护模块 |
| 3 | 面向卫星互联网领域的安全检测技术 | 研究卫星互联网链路劫持、欺骗、协议安全、终端认证等问题 | GNS3 或 OpenSAND 仿真检测模块、攻击注入、检测告警、缓解建议 |
| 4 | 面向数据要素流转的隐私集合协同计算增强技术 | 在不暴露原始数据的情况下做集合匹配、求交、求并 | 命令行或简单 Web 原型、计算开销与安全分析报告 |
| 5 | 面向海量多模态数据的实时加密与隐私保护技术 | 面向高清摄像头等终端算力受限场景，对声音、图片、视频做实时加密和隐私保护 | 采集端、处理电路、接收端原型；延时增加不超过 10%；流量不低于 1GB/s；演示不少于 30 秒 |
| 6 | 非本项目方向：海量日志异常识别 | 从 TB 级安全日志中识别罕见攻击链或异常模式，降低人工研判成本 | 日志异常识别引擎，或恶意域名检测 HTTP API，并给出召回率、误报、验证报告 |
| 7 | 面向加密通信协议的恶意行为检测技术 | 在不解密或有限解密 SSL、SSH 等会话的条件下识别异常行为 | 加密通信流量分析工具、规则或模型、正常流量与攻击流量对比实验 |
| 8 | 基于大语言模型的应用安全审计技术 | 用大模型分析 API 请求序列、参数分布、访问模式，或用大模型结合静态/动态分析发现代码漏洞 | API 安全分析工具，或多语言代码审计原型、测试用例集、检出率和误报率对比 |
| 9 | APT 供应链攻击检测与溯源系统 | 面向软件供应链识别组件版本异常、构建环境篡改、依赖混淆，并还原攻击路径 | 支持 npm、PyPI、RubyGems 等生态的检测原型、软件成分和行为分析、溯源图谱、至少 2 个典型案例复现 |

## 哪些方向更容易拿高分

### 最推荐：方向一，大模型应用安全行为监督系统

推荐理由：

| 判断点 | 原因 |
|---|---|
| 贴合热点 | 大模型智能体、工具调用、提示注入、越权操作是当前安全热点 |
| 软件可完成 | 不需要专用硬件或真实无人机，适合从空项目快速启动 |
| 演示性强 | 可以现场展示攻击输入、工具调用被拦截、告警记录、策略命中过程 |
| 评估清楚 | 可以量化攻击成功率、拦截率、误报率、检测延迟 |
| 成果完整 | 正好覆盖报告、攻击样本、攻击脚本、监控插件、实时展示这些官方要求 |

建议作品形态：做一个“智能体安全监督台”。它接在大模型应用和外部工具之间，监控邮件发送、文件读写、API 调用、代码执行等高风险动作。系统对每次工具调用给出允许、拒绝或询问，并在界面里展示攻击链、风险理由、阻断记录和复现实验。

### 备选一：方向八，基于大语言模型的应用安全审计

适合做成 API 安全审计或代码安全审计平台。优势是演示直观、数据容易构造、软件实现成本可控。风险是同质化会比较严重，不能只做“把代码丢给大模型问有没有漏洞”。要想拿高分，最好把传统安全分析方法加进去，例如污点追踪、规则扫描、调用链分析，再让大模型负责解释、归纳和辅助验证。

### 备选二：方向九，APT 供应链攻击检测与溯源

这个方向安全味很足，也容易做出图谱化演示。建议围绕 npm 和 PyPI 做依赖混淆、恶意安装脚本、版本异常、构建脚本篡改检测。高分关键是要有至少 2 个典型案例复现，并能展示从异常包到受影响资产的溯源路径。

### 稳妥备选：方向六，海量日志风险识别

适合有日志数据或能使用公开数据集的团队。系统可以做成日志解析、异常聚合、攻击链还原、恶意域名实时判定。风险是如果只是常规机器学习分类器，会显得创新不足；需要突出弱监督、攻击链聚合、可解释溯源或真实赛事平台效率提升。

### 高风险高回报：方向二、三、五

无人机、卫星互联网、实时多模态加密都很有冲击力，现场演示效果可能很好。但它们对硬件、仿真环境、性能指标或专业知识要求高。除非团队已有设备、导师资源或相关积累，否则从空项目启动风险较大。

## 高奖作品应避免的问题

| 问题 | 为什么危险 |
|---|---|
| 只有报告，没有可运行系统 | 作品赛重视工程实践，缺少可执行程序会严重削弱说服力 |
| 只有攻击，没有防御 | 赛事章程强调防御性作品，攻击复现必须服务于检测、防护或审计 |
| 只套大模型 API | 容易被认为技术深度不足，要有安全机制、评测指标和工程闭环 |
| 只做漂亮界面 | 界面只能辅助展示，核心分数来自安全技术和验证结果 |
| 没有指标 | 评委难以判断先进性和实用性，至少要有准确率、召回率、误报率、延迟、吞吐、阻断率等指标 |
| 文档混乱 | 文档规范性是明确评审项，报告结构差会影响专家快速理解 |

## 推荐项目方向草案

项目名称建议：**智安哨：面向 LLM Agent、OpenAI 兼容 API 与 MCP 的运行时安全网关**

一句话定位：从红队视角系统研究大模型智能体的提示注入、越狱、数据泄露、工具调用劫持、记忆中毒等攻击面，并在可开源智能体受控环境中复现攻击，再通过可插拔行为监督层实时审计、判定和阻断高风险行为。

核心模块建议：

| 模块 | 作用 |
|---|---|
| 开源智能体受控实验环境 | 提供一个项目内可开源、可被攻击的智能体应用，模拟真实使用场景，并预留 OpenClaw 适配接口 |
| 比赛工具沙箱 | 模拟发邮件、读写文件、调用 API、执行代码等高风险动作 |
| 攻击样本库 | 覆盖提示注入、越狱、工具调用劫持、数据泄露、记忆中毒等至少 3 类场景 |
| 监督策略引擎 | 对工具调用做允许、拒绝、询问和风险分级 |
| 异常检测模块 | 结合规则、上下文隔离、行为基线或轻量模型识别异常 |
| 可视化告警台 | 展示调用链、风险原因、阻断记录、攻击复现结果 |
| 评测报告生成 | 输出攻击成功率、阻断率、误报率、检测延迟和案例分析 |

第一阶段完成标准：

| 阶段 | 完成物 |
|---|---|
| 选题确认 | 确定方向一，并写清楚作品名称、目标用户、应用场景 |
| 最小原型 | 一个智能体应用 + 3 个模拟工具 + 一套工具调用拦截器 |
| 攻击复现 | 至少 3 类攻击，每类有输入样本、脚本、预期危害和复现步骤 |
| 防护闭环 | 对每类攻击能产生告警或阻断，并展示日志 |
| 初赛材料 | 作品报告、原创声明、演示截图、可执行程序和使用说明 |
