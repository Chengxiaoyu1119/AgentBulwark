# 真实模型接入说明

本文档说明评测运行时如何接入 OpenAI 兼容接口、DeepSeek 和智谱模型，以及透明 LLM API 网关的真实 Provider 边界。

如果你要把智安哨作为外部客户端可调用的本地模型端点，请优先看同目录下的 `本地OpenAI兼容代理接入说明.md`。当前 `/v1/chat/completions` 是透明代理：保留客户端 messages/tools，执行 Provider 前输入检查、Provider 后输出/tool call 检查，并在严格模式下验证后续执行回执。

## 设计目标

运行时评测需要在无密钥环境下复现固定实验，因此评测适配器采用“真实模型优先、本地模拟兜底”；透明代理是生产接入边界，Provider 不可用时必须返回 502，不能伪造模型响应。

调用顺序如下：

```text
评测或 Agent 请求
  -> 模型适配层
  -> OpenAI 兼容接口 / DeepSeek / 智谱真实接口
  ->（仅评测适配器）失败或未配置时切换到本地模拟模型
  -> 行为监督器继续评估工具调用
```

## 支持的模型提供方

| 提供方 | 默认接口 | 默认模型 | 作用 |
| --- | --- | --- | --- |
| OpenAI 兼容接口 | `OPENAI_COMPATIBLE_BASE_URL` + `/chat/completions` | `gpt-4.1-mini` | 接入 OpenAI 风格的模型服务或本地兼容模型网关 |
| DeepSeek | `https://api.deepseek.com/chat/completions` | `deepseek-v4-pro` | 真实大模型响应与风险观察 |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | `glm-4.6v-flashx` | 真实大模型响应与风险观察 |
| 本地模拟模型 | `local` | `agent-supervisor-sim-guard` | 仅评测/沙箱运行时兜底；透明代理不使用 |

模型名称可以按官方控制台实际可用模型调整，系统不会把模型名写死在业务逻辑里。

## 环境变量

把根目录 `.env.example` 复制成 `.env`，按需填写：

```bash
MODEL_REAL_API_ENABLED=true
MODEL_PROVIDER_PRIORITY=openai-compatible,deepseek,zhipu
MODEL_TIMEOUT_SECONDS=12

OPENAI_COMPATIBLE_API_KEY=
OPENAI_COMPATIBLE_BASE_URL=https://api.openai.com/v1
OPENAI_COMPATIBLE_MODEL=gpt-4.1-mini

DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-pro

ZHIPU_API_KEY=
ZHIPU_API_URL=https://open.bigmodel.cn/api/paas/v4/chat/completions
ZHIPU_MODEL=glm-4.6v-flashx
```

配置解释：

- `MODEL_REAL_API_ENABLED`：是否允许调用真实模型。设为 `false` 时只走本地模拟。
- `MODEL_PROVIDER_PRIORITY`：提供方优先级。可以包含 `openai-compatible`、`deepseek`、`zhipu`。
- `MODEL_TIMEOUT_SECONDS`：单次模型调用超时时间，避免比赛演示卡住。
- `OPENAI_COMPATIBLE_API_KEY`、`OPENAI_COMPATIBLE_BASE_URL`、`OPENAI_COMPATIBLE_MODEL`：OpenAI 风格模型接口配置，可接云端模型或本地兼容网关。
- `DEEPSEEK_API_KEY`、`ZHIPU_API_KEY`：真实模型密钥。
- `DEEPSEEK_MODEL`、`ZHIPU_MODEL`：调用的模型名称。

## 本地 OpenAI 兼容代理

除“平台调用外部真实模型”以外，项目还提供了一个“外部客户端调用智安哨”的本地代理：

```text
POST http://127.0.0.1:8012/v1/chat/completions
```

这个接口返回 OpenAI Chat Completions 风格结构，并额外返回 `agent_supervisor` 审计字段。它的作用不是替代模型厂商，而是把外部模型请求纳入智安哨监督链路：

```text
鉴权/契约校验 -> Provider 前输入与工具定义检查 -> 真实 Provider -> 文本/reasoning/tool call 检查 -> 审计记录
```

详细请求示例和验收方式见：`本地OpenAI兼容代理接入说明.md`。

## 失败兜底

以下情况仅在评测适配器中自动切换到本地模拟模型：

- 没有填写任何真实模型密钥。
- 接口超时。
- 真实接口返回错误。
- 网络不可用。
- `MODEL_REAL_API_ENABLED=false`。

透明代理 `/v1/chat/completions` 在上述情况返回 `502`，并携带脱敏的 `provider_failures`，不会返回本地模拟响应。

评测适配器兜底后仍会继续完成：

- 攻击样本输入。
- 智能体工具调用。
- 监督器允许、拒绝、询问、隔离判断。
- 审计日志和告警生成。
- 评测报告指标统计。

## 安全约束

真实模型只用于分析受控环境中的对抗输入，不允许执行真实危险动作。系统提示会要求模型：

- 不攻击真实外部系统。
- 不输出可用于攻击真实系统的操作步骤。
- 不执行真实工具。
- 只给出受控实验环境安全观察。

最终是否执行工具，不由模型直接决定，而由行为监督器和沙箱工具层决定。

## 验收方式

1. 不配置任何密钥，运行固定评测脚本，应看到评测适配器明确标记 `mode=fallback`；调用透明代理应返回 `502`。
2. 配置 OpenAI 兼容接口、DeepSeek 或智谱密钥，运行同一评测脚本或透明代理，应看到真实 Provider 与响应 Hash。
3. 将透明代理模型密钥改错或断网，应返回 `502`，不能伪造 Provider 响应；固定评测脚本仍可按显式 fallback 继续。
4. Provider 返回 tool call 后，使用 `/api/runtime/executions/{audit_id}/complete` 提交回执，再把 `tool_receipts` 绑定到下一轮 `role=tool` 消息。
