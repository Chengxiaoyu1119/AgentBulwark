# 宝塔服务器部署指南

本文记录 `agent-security-supervisor` 项目在宝塔 Linux 面板上的部署方式，适用于当前这台 NAT 服务器。

> 注意：本文不记录大模型 API Key、Cloudflare Tunnel Token、机场订阅链接、宝塔登录路径等敏感信息。真实密钥只放服务器 `.env`，不要写入 Git 仓库。

## 1. 当前部署结论

当前推荐部署方式：

- 后端 API 使用宝塔 Python 项目或 systemd 常驻运行，只监听服务器本机 `127.0.0.1:8012`。
- 控制台、官网、文档站都作为宝塔 HTML 项目部署静态文件。
- 控制台域名的 `/api` 和 `/v1` 由 Nginx 反向代理到后端 `127.0.0.1:8012`。
- 公网部署建议开启 API Token 鉴权：后端 `.env` 配置 `AGENT_SUPERVISOR_API_TOKEN`，控制台前端 `apps/console/.env.production` 配置同一串 `VITE_AGENT_SUPERVISOR_API_TOKEN`。
- 后端不直接暴露公网端口，公网只访问网站域名。
- Cloudflare Tunnel 本次不采用，因为服务器出站访问 Cloudflare、GitHub 和代理节点均超时。

当前线上 HTTPS 访问地址：

```text
控制台：https://xa.chengxiaoyu.top:46858
官网：https://www.xa.chengxiaoyu.top:46858
文档站：https://docs.xa.chengxiaoyu.top:46858
```

官网和文档站的生产构建会默认使用以上带端口地址做页面跳转；本地开发仍使用 `127.0.0.1` 端口，不受影响。

当前域名规划：

| 用途 | 域名 | 站点目录 |
| --- | --- | --- |
| 控制台 | `xa.chengxiaoyu.top` | `/www/wwwroot/agent-security-supervisor/apps/console/dist` |
| 官网 | `www.xa.chengxiaoyu.top` | `/www/wwwroot/agent-security-supervisor/apps/www/dist` |
| 文档站 | `docs.xa.chengxiaoyu.top` | `/www/wwwroot/agent-security-supervisor/apps/docs/build` |

当前主要端口：

| 用途 | 外部访问 | 服务器内部 |
| --- | --- | --- |
| SSH | `103.236.92.3:22308` | `22` |
| 宝塔面板 | `103.236.92.3:24604` | `37835` |
| HTTP 网站 | `103.236.92.3:58482` | `80` |
| HTTPS 网站 | `103.236.92.3:46858` | `443` |
| 后端 API | 不直接公网暴露 | `127.0.0.1:8012` |

如果服务器商后续支持标准外部 `80/443`，则可以直接访问 `https://域名`。如果仍然是 NAT 高位端口，则访问时需要带外部端口，例如 `http://xa.chengxiaoyu.top:58482`。

## 4. 服务器 `.env` 配置

服务器根目录放：

```bash
/www/wwwroot/agent-security-supervisor/.env
```

示例：

```bash
AGENT_SUPERVISOR_API_HOST=127.0.0.1
AGENT_SUPERVISOR_API_PORT=8012

# 公网部署建议开启 API 鉴权。Token 使用 32 字节以上强随机字符串。
AGENT_SUPERVISOR_AUTH_DISABLED=false
AGENT_SUPERVISOR_API_TOKEN=替换为强随机Token
AGENT_SUPERVISOR_PROXY_ALLOW_UNAUTHENTICATED_PUBLIC=false
AGENT_SUPERVISOR_CORS_ORIGINS=https://xa.chengxiaoyu.top:46858

# 启用真实大模型接口
MODEL_REAL_API_ENABLED=true
MODEL_PROVIDER_PRIORITY=deepseek,zhipu,openai-compatible
MODEL_TIMEOUT_SECONDS=30

# DeepSeek
DEEPSEEK_API_KEY=替换为真实Key
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com

# 智谱
ZHIPU_API_KEY=替换为真实Key
ZHIPU_MODEL=glm-4.6v-flashx
ZHIPU_API_URL=https://open.bigmodel.cn/api/paas/v4/chat/completions
```

生成强随机 Token 的方式：

```bash
openssl rand -hex 32
```

如果服务器没有 `openssl`，也可以使用：

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

同时控制台前端需要配置同一串 token。文件位置：

```bash
/www/wwwroot/agent-security-supervisor/apps/console/.env.production
```

内容：

```bash
VITE_AGENT_SUPERVISOR_API_TOKEN=和 AGENT_SUPERVISOR_API_TOKEN 完全一样的强随机Token
```

注意：

- `.env` 和 `apps/console/.env.production` 都是敏感文件，不提交 GitHub，不发给别人。
- `VITE_AGENT_SUPERVISOR_API_TOKEN` 会被打包进前端文件，适合比赛展示、自用部署和低强度防刷；长期公开服务仍建议加登录系统、访问白名单或 WAF。
- 本地开发可以继续使用较短超时，例如 `MODEL_TIMEOUT_SECONDS=12`；服务器公网展示建议使用 `30` 或 `45`，避免模型响应慢时过早失败。
- 如果临时只想快速展示，可以把 `AGENT_SUPERVISOR_AUTH_DISABLED=true`，但公网接口更容易被别人直接调用并消耗大模型额度。

## 5. 后端启动方式

正式启动不要使用：

```bash
npm run api
```

原因：`npm run api` 调用的是本地开发入口 `apps.api.dev_server`，该入口默认设置：

```text
AGENT_SUPERVISOR_AUTH_DISABLED=true
```

它适合本地演示，不适合作为正式公网启动入口。

正式启动命令使用：

```bash
bash -lc 'cd /www/wwwroot/agent-security-supervisor && set -a && source .env && set +a && exec /www/server/pyporject_evn/Agent-Security-Supervisor/bin/python -m uvicorn apps.api.agent_supervisor.main:app --host 127.0.0.1 --port 8012'
```

宝塔 Python 项目中填写：

| 配置项 | 值 |
| --- | --- |
| 项目名称 | `agent-security-supervisor` |
| Python 环境 | `Agent-Security-Supervisor` |
| 启动方式 | 命令行启动 |
| 项目路径 | `/www/wwwroot/agent-security-supervisor` |
| 启动用户 | `www` 或当前宝塔推荐用户 |
| 启动命令 | 上面的 `bash -lc ... uvicorn ...` |

启动后检查：

```bash
curl http://127.0.0.1:8012/api/health
```

正常返回：

```json
{"ok":true,"service":"agent-security-supervisor"}
```

## 7. Nginx 配置

### 7.1 控制台站点

控制台站点 `xa.chengxiaoyu.top` 需要把 `/api` 和 `/v1` 反代到后端。

配置核心内容：

```nginx
server
{
    listen 80;
    server_name xa.chengxiaoyu.top;
    index index.html index.htm default.htm default.html;
    root /www/wwwroot/agent-security-supervisor/apps/console/dist;

    location ^~ /api {
        proxy_pass http://127.0.0.1:8012;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }

    location ^~ /v1 {
        proxy_pass http://127.0.0.1:8012;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    access_log /www/wwwlogs/xa.chengxiaoyu.top.log;
    error_log /www/wwwlogs/xa.chengxiaoyu.top.error.log;
}
```

宝塔生成的敏感文件禁止访问、`.well-known`、缓存规则等可以保留，只要确保：

- `location ^~ /api` 存在。
- `location ^~ /v1` 存在。该路径用于 OpenAI 兼容代理 `/v1/chat/completions`。
- `location / { try_files $uri $uri/ /index.html; }` 存在。
- `/api` 和 `/v1` 规则放在普通静态规则之前。

### 7.2 官网站点

官网是纯静态站点：

```nginx
server
{
    listen 80;
    server_name www.xa.chengxiaoyu.top;
    index index.html index.htm default.htm default.html;
    root /www/wwwroot/agent-security-supervisor/apps/www/dist;

    location / {
        try_files $uri $uri/ /index.html;
    }

    access_log /www/wwwlogs/www.xa.chengxiaoyu.top.log;
    error_log /www/wwwlogs/www.xa.chengxiaoyu.top.error.log;
}
```

### 7.3 文档站

文档站是 Docusaurus 静态站点：

```nginx
server
{
    listen 80;
    server_name docs.xa.chengxiaoyu.top;
    index index.html index.htm default.htm default.html;
    root /www/wwwroot/agent-security-supervisor/apps/docs/build;

    location / {
        try_files $uri $uri/ /index.html;
    }

    access_log /www/wwwlogs/docs.xa.chengxiaoyu.top.log;
    error_log /www/wwwlogs/docs.xa.chengxiaoyu.top.error.log;
}
```

```bash

```

## 8. NAT 访问和 DNS

当前服务器是 NAT 服务器，外部不是直接访问内部 80/443，而是：

```text
103.236.92.3:58482 -> 服务器内部 80
103.236.92.3:46858 -> 服务器内部 443
```

DNS 记录应该指向外部公网 IP：

| 主机记录 | 类型 | 记录值 |
| --- | --- | --- |
| `xa` | A | `103.236.92.3` |
| `www.xa` | A | `103.236.92.3` |
| `docs.xa` | A | `103.236.92.3` |

如果 DNS 托管在 Cloudflare，但不用 Cloudflare 代理，三条记录要设置为：

```text
仅 DNS / 灰云
```

不要开启橙云代理，因为 Cloudflare 免费代理不支持 `58482` 这种自定义 HTTP 端口。

访问地址：

```text
http://xa.chengxiaoyu.top:58482
http://www.xa.chengxiaoyu.top:58482
http://docs.xa.chengxiaoyu.top:58482
```

如果配置了 HTTPS NAT：

```text
https://xa.chengxiaoyu.top:46858
https://www.xa.chengxiaoyu.top:46858
https://docs.xa.chengxiaoyu.top:46858
```

是否能不带端口访问，取决于服务器商是否把外部标准 `80/443` 转发给本机。

## 9. SSL 证书

如果外部 `80/443` 不是标准端口，宝塔的普通 HTTP 文件验证可能失败。原因是证书机构默认访问：

```text
http://域名/.well-known/acme-challenge/...
```

默认只走 80 端口，不会自动访问 `58482`。

可选方案：

- 使用 DNS 验证申请证书。
- 在域名服务商手动添加 TXT 验证记录。
- 使用已有证书，在宝塔 SSL 页面手动粘贴证书和私钥。
- 让服务器商开放或映射标准外部 `80/443`。

宝塔申请失败时常见报错：

```text
已尝试验证15次，最大验证次数为15
```

这通常不是项目问题，而是证书机构无法从公网标准端口访问验证文件。

## 10. Cloudflare Tunnel 结论

本次尝试过 Cloudflare Tunnel，但最终不采用。

失败原因：

- 服务器可以访问国内站点，例如百度、QQ、阿里云。
- 服务器访问 `api.cloudflare.com:443` 超时。
- 服务器访问 `github.com:443` 超时。
- `cloudflared` 日志显示：

```text
DNS Resolution PASS
UDP Connectivity FAIL
TCP Connectivity FAIL
Cloudflare API FAIL
```

说明 DNS 能解析，但到 Cloudflare 的 TCP/UDP 连接走不通。

也尝试过安装 `mihomo` 代理客户端：

- 第一份订阅 7 个日本节点全部 TCP 超时。
- 第二份订阅节点入口依赖 Cloudflare/CDN，仍然连接超时。
- Windows SSH 反向代理只能临时解决，电脑关机或 SSH 断开后服务会中断，不适合作为正式部署。

因此当前正式部署不依赖 Cloudflare Tunnel。

## 12. 常见问题

### 12.1 `curl http://127.0.0.1:8012/api/health` 正常，但公网 `/api/health` 404

说明后端正常，Nginx 控制台站点没有正确配置 `/api` 反代。

检查：

```bash
grep -R "location \\^~ /api" -n /www/server/panel/vhost/nginx /www/server/nginx/conf 2>/dev/null
nginx -t
/etc/init.d/nginx reload
```

### 12.2 本机 Host 验证 200，但浏览器 502

优先检查：

- DNS 是否解析到 `103.236.92.3`。
- 是否访问了正确 NAT 外部端口 `58482`。
- Cloudflare DNS 是否为灰云。
- Nginx 是否重载成功。
- 宝塔站点是否指向正确 `dist/build` 目录。

### 12.3 `www.xa` 或 `docs.xa` 无法解析

检查 DNS 记录是否存在：

```cmd
nslookup xa.chengxiaoyu.top
nslookup www.xa.chengxiaoyu.top
nslookup docs.xa.chengxiaoyu.top
```

三条都应解析到：

```text
103.236.92.3
```

### 12.4 文档站依赖审计问题

文档站是 Docusaurus 构建链路，最终部署的是静态文件：

```text
apps/docs/build
```

运行时不暴露 Node 开发服务器。依赖审计里的构建期残余项优先级低于后端公网接口和控制台运行安全，但后续升级 Docusaurus/相关依赖时应单独处理。

### 12.5 API Token 鉴权说明

当前推荐 `.env` 使用：

```bash
AGENT_SUPERVISOR_AUTH_DISABLED=false
AGENT_SUPERVISOR_API_TOKEN=强随机Token
AGENT_SUPERVISOR_PROXY_ALLOW_UNAUTHENTICATED_PUBLIC=false
```

影响：

- 控制台前端会自动携带 `VITE_AGENT_SUPERVISOR_API_TOKEN`，用户正常打开网站不需要手动输入 token。
- 外部访问者如果绕过网页直接扫 `/api` 或 `/v1/chat/completions`，没有 token 会被拒绝。
- AI 大模型 Key 仍然只放在服务器端 `.env`，不会直接暴露到浏览器。
- `VITE_AGENT_SUPERVISOR_API_TOKEN` 会进入前端构建产物，适合比赛展示和基础防刷，不等同于完整登录系统。

如果项目只是临时演示或测试，可以把 `AGENT_SUPERVISOR_AUTH_DISABLED=true`，但正式长期公网运行建议保留 token 鉴权，并继续配合限速、WAF 或登录系统。

## 13. 更新部署流程

```bash

git pull

npm --prefix apps/console ci
npm --prefix apps/www ci
```

然后在宝塔 Python 项目里重启后端，或执行对应的后端服务重启操作。

如果在本地电脑已经配置好 token 并构建，再打包上传服务器：

```text
C:\Users\Chengxiaoyu\Documents\GitHub\agent-security-supervisor\.env
C:\Users\Chengxiaoyu\Documents\GitHub\agent-security-supervisor\apps\console\.env.production
```

这两个文件可以放进本地私有部署压缩包，但不要提交 GitHub，也不要发给别人。上传到服务器后：

1. 确认服务器 `/www/wwwroot/agent-security-supervisor/.env` 里的 `AGENT_SUPERVISOR_API_TOKEN` 存在，并保留服务器自己的模型配置，例如 `MODEL_TIMEOUT_SECONDS=30`。
2. 确认服务器 `/www/wwwroot/agent-security-supervisor/apps/console/.env.production` 里的 `VITE_AGENT_SUPERVISOR_API_TOKEN` 与后端 token 完全一致。
3. 如果上传了本地已构建好的 `apps/console/dist`，服务器可以不重新构建控制台前端。

5. 上传后在宝塔 Python 项目里重启后端。

## 14. 当前不建议做的事

- 不要把 `.env`、API Key、Tunnel Token、机场订阅链接提交到 GitHub。
- 不要用 `npm run api` 作为正式后端启动方式。
- 不要让后端直接监听 `0.0.0.0` 暴露公网，除非加好鉴权和防火墙。
- 不要在不清楚规则含义时启用服务器商安全组，避免把 SSH NAT 入口挡掉。
- 不要依赖 Windows SSH 反向代理作为正式服务链路。
- 不要把本地生成的发布包、exe、旧提交包继续放进项目运行目录。
