## 摘要

摘要建议控制在 500-800 字，回答 5 个问题：

1. 大模型智能体为什么会带来新的安全风险。
2. 本作品研究了哪些攻击面。
3. 本作品如何复现攻击。
4. 本作品如何监督和防御。
5. 实验结果证明了什么。

推荐摘要逻辑：

> 随着大语言模型从聊天工具演进为可调用文件、邮件、API、代码执行器和长期记忆的智能体系统，传统输入输出安全检查已经难以覆盖真实风险。本作品从红队视角系统研究提示注入、模型越狱、数据泄露、滥用风险、工具调用劫持、记忆中毒和环境感知污染等攻击面，构建对抗样本、越狱测试用例和智能体攻击脚本，并在可控受控环境中复现攻击链。针对上述风险，作品设计了可旁路部署的行为监督机制，对智能体集群与外部工具之间的交互进行实时审计，基于策略和异常判定输出允许、拒绝、询问、隔离等决策。实验部分对比无防护和有防护状态下的攻击成功率、阻断率、误报率和检测延迟，验证平台在大模型应用安全评测和防御验证中的可行性。

## 1. 研究背景与问题定义

### 1.1 背景

说明大模型应用正在从“回答问题”变成“执行任务”：

- 可以调用工具。
- 可以读写文件。
- 可以访问业务 API。
- 可以执行代码。
- 可以保存长期记忆。
- 可以由多个 agent 协同完成复杂任务。

### 1.2 安全问题

指出传统安全防护不足：

- 只检查最终输出，无法发现中间工具调用风险。
- 只做关键词过滤，难以识别多轮越狱和上下文污染。
- 智能体拥有工具权限后，错误决策会变成真实动作。
- 多 agent 协同会放大攻击链复杂度。

### 1.3 研究目标

本作品目标：

- 系统研究大模型智能体攻击面。
- 构建攻击样本和脚本。
- 搭建可控攻击受控实验环境。
- 设计行为监督机制。
- 形成可量化的防御评测。

## 3. 攻击面分析

这一章是报告核心，必须优先写好。

### 3.1 攻击面分类

| 攻击面 | 研究问题 | 典型危害 |
|---|---|---|
| 提示注入 | 恶意输入能否覆盖系统规则 | 泄露上下文、误调用工具 |
| 模型越狱 | 模型能否被诱导绕过安全约束 | 输出违规内容、执行不当动作 |
| 数据泄露 | 智能体能否被诱导读取敏感数据 | 文件、记忆、比赛数据泄露 |
| 滥用风险 | 模型能力能否被滥用于异常业务 | 邮件滥发、接口滥调 |
| 工具调用劫持 | 模型是否会错误选择或滥用工具 | 文件读写、API 越权、代码执行 |
| 记忆中毒 | 恶意记忆能否影响未来任务 | 长期行为偏移 |
| 环境感知污染 | 工具返回或环境配置能否误导模型 | 错误决策、策略绕过 |

### 3.2 每类攻击的写法模板

6. 智能体攻击脚本。
7. 复现实验。
8. 危害分析。
9. 防御策略。

### 3.3 主演示攻击建议

初赛重点展示 5 类：

| 优先级 | 攻击场景 | 展示价值 |

## 5. 防御策略

### 5.1 输入过滤

用于识别：

- 越狱提示。
- 忽略系统规则。
- 诱导泄露。
- 伪造权限。
- 恶意工具调用意图。

### 5.2 输出过滤

用于识别：

- 敏感数据泄露。
- 不当操作建议。
- 工具调用解释异常。
- 与任务目标无关的高风险输出。

### 5.3 上下文隔离

核心思想：

- 系统指令、用户输入、工具返回、长期记忆、环境信息分层处理。
- 工具返回内容不能直接提升权限。
- 记忆内容不能覆盖系统策略。

### 5.4 工具权限控制

权限策略：

- 邮件外发默认询问。
- 文件越界默认拒绝。
- 代码执行默认隔离。
- 高敏 API 默认需要策略校验。
- 记忆写入需要记录来源。

### 5.5 模型行为监测

监测内容：

- 是否偏离任务目标。
- 是否主动请求敏感数据。
- 是否连续尝试越权调用。
- 是否在多轮对话中规避限制。

## 6. 实验设计

### 6.1 实验目标

验证 3 件事：

1. 攻击能被复现。
2. 监督器能捕获关键行为。
3. 防御策略能降低攻击成功率。

### 6.2 实验分组

| 分组 | 说明 |
|---|---|
| 无防护组 | 监督器只记录不阻断 |
| 有防护组 | 监督器按策略阻断或询问 |
| 隔离组 | 高风险动作进入沙箱执行 |

### 6.3 指标

| 指标 | 含义 |
|---|---|
| 攻击成功率 | 攻击是否达成预期危害 |
| 阻断率 | 高风险攻击被拦截比例 |
| 误报率 | 正常任务被错误阻断比例 |
| 检测延迟 | 从工具调用发生到告警产生的时间 |
| 复现稳定性 | 同一脚本多次运行是否稳定 |

## 8. 创新点总结

报告和答辩统一突出 5 点：

1. **执行层安全检查点**：把安全检查从模型对话层前移到工具执行前，直接约束目标资源和副作用。
2. **工具契约规范化**：统一处理工具白名单、Unicode、编码路径、收件人和 API 路径，未知工具默认拒绝。
3. **副作用实证评测**：攻击成功由文件、邮件、API、记忆和模型输出等沙箱副作用断言，不由防护开关直接决定。
4. **独立留出集**：以人工固定标签的攻击和正常样本独立测量召回率、误报率与策略匹配率。
5. **四类处置闭环**：允许、拒绝、询问、隔离配合 audit_hash、review_hash 和通用 AgentToolGuard；OpenClaw Hook 作为可选兼容。
