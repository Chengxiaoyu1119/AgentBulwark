# 项目立项说明

项目名称：智安哨：面向 LLM Agent、OpenAI 兼容 API 与 MCP 的运行时安全网关
对应赛事：第十一届上海市大学生网络安全大赛暨“磐石行动”2026第四届全国高校网络安全攻防活动·信息安全作品赛
作品类别：软件作品；所属方向：安全检测
整理日期：2026-08-10

## 1. 项目结论

本项目严格围绕信息安全作品赛软件作品的安全检测方向展开，核心不是单纯开发一个安全后台，而是构建一个“攻击面研究 + 攻击复现 + 行为监督 + 防御评测”的闭环平台。

项目主线如下：

> 红队攻击面研究 -> 攻击样本与脚本复现 -> 智能体受控实验环境验证 -> 行为监督拦截 -> 防御策略评测 -> 告警与报告展示

比赛方要求从红队视角研究大语言模型和智能化应用的典型攻击面，并设计可嵌入或旁路的行为监督机制。因此，本项目把“攻击面研究”放在第一位，把“行为监督系统”作为证明攻击研究结果、验证防御策略和支撑现场演示的原型系统。

## 2. 赛题对应关系

| 方向目标 | 本项目对应设计 |
|---|---|
| 研究提示注入、模型越狱、训练数据泄露、滥用风险、工具调用劫持、记忆中毒、环境感知污染等攻击面 | 建立 7 类攻击面研究库，每类包含原理、样本、脚本、复现步骤、危害和防御策略 |
| 构造对抗性输入 | 建立对抗样本库和越狱测试用例集 |
| 每类场景包括模型对抗样本与越狱测试用例集 | 主演示攻击面均提供可运行样本和测试用例 |
| 每类场景包括智能体攻击脚本 | 提供单 agent 脚本和多 agent 协同攻击链脚本 |
| 拦截智能体集群与外部工具的交互 | 在智能体和工具层之间加入行为监督器 |
| 对工具调用、代码执行、文件访问实时审计与异常判定 | 监控邮件、文件、API、代码执行、记忆、环境读取等工具行为 |
| 基于允许、拒绝、询问策略或异常检测模型进行监控 | 策略引擎输出允许、拒绝、询问、隔离四类决策 |

| 基座模型检测或过滤原型 | 实现输入过滤、输出过滤、上下文隔离、行为监测 |
| 监督端实时展示告警或阻断记录 | Web 端展示告警、阻断、询问、调用链和指标 |

## 3. 目标用户与使用场景

目标用户包括：

| 用户 | 需求 |
|---|---|
| 比赛评委 | 快速理解团队研究了哪些攻击面、如何复现、如何防御、效果如何 |
| 大模型应用开发者 | 了解智能体接入工具后可能出现的真实风险 |
| 企业安全运营人员 | 观察 agent 工具调用、代码执行、文件访问中的异常行为 |
| 教学与科研人员 | 使用平台作为大模型应用安全实验环境 |

典型使用场景：

1. 评委打开 Web 系统，先看到 7 类攻击面总览。
2. 选择“工具调用劫持”攻击剧本，运行无防护实验。
3. 目标智能体被诱导调用文件工具或 API 工具，产生风险。
4. 打开行为监督器后重新运行同一攻击。
5. 监督器给出风险原因、策略命中和阻断记录。
6. 系统自动汇总攻击成功率、阻断率、误报率和检测延迟。

## 4. 攻击面研究范围

第一版覆盖 7 类攻击面，当前内置 17 个可复现攻击剧本。所有剧本都要同时包含模型对抗样本、越狱测试用例集、智能体攻击脚本、攻击链路、检测信号和安全边界，避免只做页面演示而缺少作品目标的材料。

| 攻击面 | 风险说明 | 第一版状态 |
|---|---|---|
| 提示注入 | 利用恶意提示覆盖系统规则，诱导模型泄露信息或调用工具 | 重点演示 |
| 模型越狱 | 通过角色扮演、多轮引导等方式绕过模型安全限制 | 重点演示 |
| 数据泄露 | 诱导智能体读取沙箱文件、记忆内容、模拟比赛数据 | 重点演示 |
| 工具调用劫持 | 诱导模型错误调用邮件、文件、API、代码工具 | 重点演示 |
| 记忆中毒 | 向长期记忆写入恶意指令，影响后续任务 | 重点演示 |
| 滥用风险 | 诱导发送违规邮件、批量调用接口、执行异常比赛任务动作 | 研究补充 |
| 环境感知污染 | 伪造配置、环境变量或工具返回值误导模型决策 | 研究补充 |

每类攻击沉淀为 8 项材料：

| 材料 | 说明 |
|---|---|
| 攻击原理 | 用直白语言解释攻击为什么能发生 |
| 攻击样本 | 具体对抗输入文本 |
| 越狱测试用例 | 可重复测试的提示与期望结果 |
| 智能体攻击脚本 | 自动化调用目标智能体和工具 |
| 复现步骤 | 评委或团队成员可以按步骤复现 |
| 危害说明 | 说明该攻击会造成什么业务后果 |
| 防御策略 | 输入过滤、输出过滤、上下文隔离、权限控制等 |
| 实验结果 | 无防护和有防护对比数据 |

## 5. 作品创新点

| 创新点 | 说明 |
|---|---|
| 攻击面研究优先 | 不是把大模型接进普通安全后台，而是围绕方向目标系统研究智能体攻击面 |
| 多 agent 红队攻击链 | 使用规划 agent、样本生成 agent、执行 agent、评测 agent 协同构造攻击 |
| 行为监督插桩 | 在智能体和工具层之间插入监督器，监控真实行为而不只检查提示文本 |
| 攻防对比评测 | 同一攻击可以在无防护和有防护状态下对比运行 |
| 沙箱化真实工具 | 邮件、文件、API、代码执行都具备真实调用形态，但限定在假数据和安全沙箱内 |
| 可解释告警 | 每次阻断都说明风险来源、触发规则和建议防御策略 |
| 现场可演示闭环 | 页面可以从攻击面、攻击链、工具调用、阻断记录一路讲到评测报告 |

## 6. 验收指标

| 指标 | 第一版目标 |
|---|---|
| 攻击面覆盖 | 7 类有研究说明，22 个剧本可系统复现，其中 5 个聚焦学生比赛对象 |
| 攻击样本 | 每类主演示攻击不少于 3 条样本 |
| 越狱用例 | 每类主演示攻击不少于 2 条测试用例 |
| 攻击脚本 | 每类主演示攻击至少 1 个可运行脚本 |
| 多 agent 攻击链 | 至少 1 条完整协同攻击链 |
| 监督对象 | 覆盖工具调用、代码执行、文件访问、API 调用 |
| 策略结果 | 支持允许、拒绝、询问、隔离 |
| 评测指标 | 输出攻击成功率、阻断率、误报率、检测延迟 |
| 演示稳定性 | DeepSeek/智谱不可用时可切换模拟模型完整演示 |
| 文档材料 | 形成技术报告、原创性声明、报名表和答辩演示材料 |

## 7. 技术边界

本项目只在本地受控环境、假比赛数据和沙箱工具内复现攻击。

明确不做：

- 不攻击真实外部系统。
- 不读取用户真实文件。
- 不发送真实邮件。
- 不执行破坏性命令。
- 不提供可直接用于真实目标攻击的外部投递能力。

允许做：

- 在沙箱目录内模拟文件泄露。
- 在假 outbox 中模拟邮件发送。
- 在模拟 API 中复现越权调用。
- 在受限代码执行器中运行无破坏性脚本。
- 在假记忆库中复现记忆中毒。
