# 业务组件目录契约

`components` 只保存可渲染的业务组件，目录名代表**数据与行为的拥有者**，不代表当前页面上的摆放位置。

## 目录边界

| 目录 | 责任 | 允许依赖 |
| --- | --- | --- |
| `ui` | 跨业务域复用的基础交互、布局、状态和证据展示 | Ant Design、设计 Token |
| `gateway` | OpenAI 代理、MCP、网关 Trace、接入向导和执行证据 | `ui`、`app` 契约、类型 |
| `audit` | 风险事件、审批、审计和执行回执视图 | `ui`、类型 |
| `settings` | Provider、Agent 权限、策略和记忆治理配置 | `ui`、类型 |

## 放置规则

1. 页面只编排数据和业务组件；基础按钮、标签、指标卡、字段标签和布局进入 `ui`。
2. 网关组件统一进入 `gateway`，即使它们从“设置”页面打开，也不能按页面位置放入 `settings`。
3. 业务目录之间不直接复用组件；需要跨域时先提取到 `ui`，避免循环依赖和隐式耦合。
4. 测试与被测组件同目录放置，测试文件使用同名 `.test.tsx` 后缀。
5. 新目录必须同时更新 `scripts/frontend-governance-check.mjs` 的目录白名单和本契约表。

`npm run ui:audit` 会检查目录白名单、生产依赖闭包、跨域组件导入、基础控件封装和设计 Token；门禁失败时先修正归属，再增加代码。
