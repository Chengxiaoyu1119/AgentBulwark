# 风险边界

AgentBulwark 按请求、模型、行动和证据四层组织风险检查。文本过滤器负责发现输入与输出信号，身份、策略、Schema、目标和 MCP 闸门负责决定是否允许产生副作用。

## 四层边界

| 层 | 主要输入 | 典型风险 | 控制点 |
| --- | --- | --- | --- |
| 请求层 | 提示、外部上下文、身份和 Session | 提示注入、越狱、伪造授权 | 输入检查、身份绑定、Session 校验 |
| 模型层 | 模型输出、工具描述和 Tool Call | 输出污染、工具定义投毒、未知工具 | 响应标准化、工具登记、Schema 检查 |
| 行动层 | 参数、目标、权限和审批 | 越权、路径穿越、数据外发、重复执行 | 四态策略、目标约束、一次性审批、MCP 闸门 |
| 证据层 | Trace、Hash、回执和 HMAC | 声明与事实不一致、链路断裂 | 请求链绑定、回执校验、离线核验 |

## 不可信上下文

来自用户、检索结果、文件或第三方工具的数据都按不可信上下文处理。上下文可以影响模型判断，但不能直接扩大 Agent 权限；进入 Provider 前先经过请求检查，进入工具阶段后仍要重新校验行动边界。

## 工具契约

工具名称、描述、Schema 和目标属于安全契约的一部分：

- 未登记工具不会进入 MCP；
- Schema 新增字段或发生漂移时需要重新审核；
- 参数类型、路径、主机和端口必须符合当前策略；
- 工具返回内容不会自动获得更高信任级别。

## 真实行动

只有 MCP 闸门允许的 Tool Call 才能产生外部副作用。ALLOW 允许继续，DENY 阻断，ASK 等待一次性审批，ISOLATE 在隔离边界内处理。多个规则同时命中时，按 DENY > ISOLATE > ASK > ALLOW 收敛。

## Provider 出口

Provider 路由固定到主机、协议、端口和路径。服务禁止自动重定向和系统代理偷传凭证；Provider 地址、响应格式、超时或 DNS 发生异常时，流程进入明确失败终态。

## 来源状态

| 状态 | 含义 | 使用边界 |
| --- | --- | --- |
| proved | 客户端携带一次性关联凭证，网关完成密码学来源验证 | 可以标记为来源已证明 |
| correlated | 根据请求链字段和时间窗口完成关联 | 只能标记为已关联，不能写成已证明 |
| unknown | 无法可靠关联来源 | 高风险工具默认阻断或进入审批 |

## 最小验证清单

~~~text
正常请求        -> Provider 调用、Trace、Hash 和回执一致
提示注入        -> Provider 调用次数为 0
未知工具        -> 不进入 MCP
参数或目标变化  -> 原审批失效且上游执行次数为 0
~~~

风险边界的目标不是预测所有模型行为，而是在每个可产生副作用的边界设置可验证的拒绝、审批和证据终态。
