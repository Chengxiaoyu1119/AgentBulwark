# 本地开发

本文档只覆盖单机本地运行。生产 Provider 与 MCP 凭证由后端读取，运行数据库和质量产物统一写入 `apps/api/runtime/`，不进入 Git。

## 环境要求

- Windows、macOS 或 Linux。
- Node.js 22+ 和 npm 9.6+。
- Python 3.11+。
- PowerShell 7+（Windows 默认 PowerShell 也可运行启动脚本）。

## 安装

```powershell
git clone https://github.com/Chengxiaoyu1119/AgentBulwark.git
cd AgentBulwark
npm run install:all
Copy-Item .env.example .env
```

`npm run install:all` 安装 `apps/console/`、`apps/www/`、`apps/docs/` 的 Node 依赖和 API 开发依赖，不在仓库根目录生成项目依赖。

## 启动

```powershell
npm run dev
```

启动脚本会：

1. 检查 `127.0.0.1:8012` 是否可用；
2. 构建最新控制台资源；
3. 启动 FastAPI API 和本地控制台；
4. 在 API 就绪后打开浏览器。

服务地址：`http://127.0.0.1:8012`。

只启动控制台（用于前端开发）：

```powershell
npm run dev:console
```

只启动 API（用于后端调试）：

```powershell
npm run api:dev
```

## 配置原则

1. 从 `.env.example` 复制 `.env`，不要把真实凭证写入前端代码。
2. 所有运行配置使用 `AGENT_SUPERVISOR_*` 环境变量；这是兼容标识，不要在一次普通功能修改中改名。
3. Provider 地址必须固定主机、协议、端口和路径；重定向、系统代理和未登记目标默认拒绝。
4. 本地免登录只适用于回环地址；生产模式应使用后端 Bearer 鉴权。
5. 干净安装默认要求每个 Agent 显式登记工具、模型和 MCP 上下文范围；未建立四类边界时请求保持阻断。
6. `.env`、`apps/api/runtime/`、控制台依赖和构建产物都被 Git 忽略。

## 验证命令

提交前先运行直接相关检查，再运行全量门禁：

```powershell
npm run console:test
npm run api:test
npm run verify
```

确定性闭环会启动仓库内的 HTTP Provider 和 MCP stdio 子进程：

```powershell
npm run verify:live:fixture
```

外部 Provider 烟测默认关闭。只有显式设置开关才会访问外部服务：

```powershell
$env:AGENT_SUPERVISOR_LIVE_SMOKE = "true"
npm run verify:live
```

只验证一个已配置的真实 Provider 时，不需要 MCP 或 HMAC。该模式会对指定 Provider 发起 3 条固定、低输出请求，验证请求、Trace 和 Hash 绑定，并确认三类注入在 Provider 前被阻断：

```powershell
# DeepSeek
$env:AGENT_SUPERVISOR_LIVE_SMOKE = "true"
$env:AGENT_SUPERVISOR_LIVE_SCOPE = "provider"
$env:AGENT_SUPERVISOR_LIVE_PROVIDER_ID = "deepseek"
$env:AGENT_SUPERVISOR_LIVE_REPORT_PATH = "apps/api/runtime/quality/real-provider-compat/deepseek/last-run.json"
npm run verify:live

# 智谱
$env:AGENT_SUPERVISOR_LIVE_PROVIDER_ID = "zhipu"
$env:AGENT_SUPERVISOR_LIVE_REPORT_PATH = "apps/api/runtime/quality/real-provider-compat/zhipu/last-run.json"
npm run verify:live
```

Provider 模式要求精确选择 `deepseek` 或 `zhipu`。未配置、模型冲突或固定路由无效时不会发起 Provider 请求，并在报告中保留失败原因。该报告的 `mcp_status` 为 `not_run`、`mcp_reason` 为 `provider-scope`，表示 MCP 不属于本次验证范围，不表示 Provider 验证失败。

验证真实 Tool Calling 与服务端托管只读执行时，使用 `provider-tool` 范围。该范围复用已登记 Agent、任务档案和 `file.read`，不需要外部 MCP；任务档案应只允许 `file.read` 和 `public/*`。需要设置 Agent Token、Agent ID 和任务 ID：

```powershell
$env:AGENT_SUPERVISOR_LIVE_SCOPE = "provider-tool"
$env:AGENT_SUPERVISOR_LIVE_PROVIDER_ID = "deepseek"
$env:AGENT_SUPERVISOR_LIVE_AGENT_ID = "<已登记的 Agent ID>"
$env:AGENT_SUPERVISOR_LIVE_AGENT_TOKEN = "<该 Agent Token>"
$env:AGENT_SUPERVISOR_LIVE_TASK_ID = "<只读任务 ID>"
$env:AGENT_SUPERVISOR_LIVE_REPORT_PATH = "apps/api/runtime/quality/real-provider-compat/deepseek/tool-call-last-run.json"
npm run verify:live

$env:AGENT_SUPERVISOR_LIVE_PROVIDER_ID = "zhipu"
$env:AGENT_SUPERVISOR_LIVE_REPORT_PATH = "apps/api/runtime/quality/real-provider-compat/zhipu/tool-call-last-run.json"
npm run verify:live
```

报告中的 `tool_call_status=passed` 表示真实 Tool Call、任务范围、服务端执行和回执已经串通；`integrity_mode=hash-bound` 表示本地未配置 HMAC，`hmac-signed` 表示同时完成 HMAC 签名。Provider 接受工具定义但本次未生成 Tool Call 时记录 `inconclusive`，不伪装成通过或网关故障。缺少 Agent 或任务配置时保持 `not_run`，不会先发送普通 Provider 请求。

完整 Provider + MCP 闭环还需要在后端进程中配置 `AGENT_SUPERVISOR_AUDIT_HMAC_KEY`（不要写入前端或报告）。烟测会先检查 HMAC 和 MCP 上游状态；配置缺失时不会发起 Provider 请求，直接返回 `not_run`，不会伪造通过。

烟测报告写入被忽略的 `apps/api/runtime/quality/`。真实 Provider 请求会按普通网关链路写入审计和 Trace，但不会修改策略、任务授权或 MCP 配置。

## 运行数据位置

| 内容                        | 路径                                               | 是否提交 |
| --------------------------- | -------------------------------------------------- | -------- |
| 运营 SQLite、策略和审计数据 | `apps/api/runtime/operational/`                    | 否       |
| 质量检查和覆盖率            | `apps/api/runtime/quality/`                        | 否       |
| 浏览器测试临时数据          | `apps/api/runtime/e2e/`                            | 否       |
| 运行数据备份                | `apps/api/runtime/backups/`                        | 否       |
| 前端依赖和构建结果          | `apps/console/node_modules/`、`apps/console/dist/` | 否       |

不要手动清空 `operational/`。需要预览可清理的本地临时产物时运行：

```powershell
& .\scripts\clean-local-artifacts.ps1
```

确认预览列表后，才执行实际清理：

```powershell
& .\scripts\clean-local-artifacts.ps1 -Apply
```

清理脚本只操作仓库内列明且超过最小保留时间的缓存和测试目录，并保护 `.env`、媒体资料、运行数据库和控制台依赖。要扩大或缩短保留时间，使用 `-MinimumAgeHours <小时数>`；不要对 `operational/` 或 `backups/` 手动执行清理。

## 备份、验证与恢复

备份会生成带 SQLite 一致性校验、文件 Hash 和可选 HMAC 的 ZIP 归档。路径必须位于 `apps/api/runtime/` 之外，避免运行数据和备份同时丢失。

```powershell
# 查看全部参数
npm run backup:help

# 创建归档；npm 命令后的 -- 用于把参数交给 Python 子命令
npm run backup:create -- --output D:\backups\agent-bulwark-20260920.zip

# 校验清单、Hash、SQLite 完整性和已配置的 HMAC
npm run backup:verify -- --input D:\backups\agent-bulwark-20260920.zip
```

恢复会替换目标运行目录，必须先停止服务并显式确认。恢复默认保留回滚目录；只有确认不需要回滚时才传入 `--discard-rollback`。

```powershell
npm run backup:restore -- --input D:\backups\agent-bulwark-20260920.zip --confirm-offline-restore
```

历史裸 SQLite/JSON 快照不等同于当前 ZIP 归档格式，不应当作可随意清理的缓存。

## 常见故障

| 现象                 | 处理                                                         |
| -------------------- | ------------------------------------------------------------ |
| `8012` 端口占用      | 关闭占用进程后重新运行 `npm run dev`                         |
| 控制台显示 API 离线  | 先确认 API 就绪，再点击页面的重新读取；查看终端错误          |
| 生产模式返回 `401`   | 配置后端 Bearer Token，并使用 `Authorization` 请求头         |
| Provider 请求被拒绝  | 检查地址是否固定、已登记且没有重定向                         |
| 工具调用进入审批     | 检查 Agent、Session、Schema、目标和当前策略版本              |
| 闭环报告为 `not_run` | 这是外部烟测默认行为；确定性验证请运行 `verify:live:fixture` |

## 开发边界

生产入口不得导入研究或历史资料目录。不要重新引入 Docker、任意命令执行、旧实验路由或前端共享 Token。修改策略、审批、MCP、Provider 出口或证据链时，必须补充失败路径测试。
