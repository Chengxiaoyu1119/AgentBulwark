# 大模型防火墙研究证据与产品决策

更新时间：2026-09-16

## 结论

本项目方向应收敛为“面向 LLM Agent、OpenAI 兼容 API 与 MCP 的运行时安全网关”，但不能把它宣传成一个提示词分类器。现有论文共同说明：提示词注入的核心风险不是模型说了什么，而是不可信数据能否改变 Agent 的目标、工具参数、权限边界和外部副作用。

因此，产品必须在模型外建立确定性执行边界：来源分级、任务对齐、Provider 前后检查、Tool Call 权限与参数检查、执行前闸门、服务端观察回执和可追踪事件。输入检测只是信号层，不是最终安全边界。

## 事实、推论与尚未证明

### 已有论文直接支持的事实

1. 间接提示词注入是可复现的 Agent 风险。InjecAgent 包含 1,054 个用例、17 类用户工具和 62 类攻击者工具；ReAct GPT-4 在其设置下的攻击成功率达到 24%。
2. 防护效果必须和正常任务效用一起测。AgentDojo 同时提供 97 个真实任务与 629 个安全测试，指出模型在无攻击时也会失败，单报“拦截率”会误导。
3. 固定攻击样本不足以证明稳健。Zhan 等对 8 种间接注入防御做自适应攻击，均被绕过，攻击成功率持续超过 50%。
4. 指令与数据需要结构化分离。StruQ 将可信 Prompt 与不可信数据分通道，并配合专门训练的模型；Instruction Hierarchy 强调高优先级指令相对用户与第三方不可信数据的优先性。
5. 系统级约束比单一输入分类更接近可靠边界。CaMeL 在模型外显式控制数据流和 capability；Task Shield 检查每条指令和 Tool Call 是否服务于用户目标；DRIFT 同时约束控制流、数据流和记忆流。
6. 国内研究已把提示注入、间接提示注入、越狱和后门列为独立攻击模式，并强调在完整生命周期中平衡安全、隐私与模型效用。

### 基于论文与当前代码的工程推论

1. 产品应该像 WAF 一样处于请求链路中，而不是要求用户打开实验室手工运行脚本。
2. “被模型拒答”不等于“网关阻断”。验证必须分别记录 Provider 是否调用、Tool Call 是否返回、是否执行、执行由谁观察、回执是否绑定同一请求。
3. Tool Call 的真实副作用是最终边界。透明代理可检查并扣留 Tool Call，但调用方仍可能绕开决策；托管执行器和 MCP Gateway 才能形成强制执行点。
4. UI 的主对象应该是请求和事件，而不是攻击脚本、比赛报告或技术模块。每条事件应按“输入 → 模型 → 工具 → 执行”展示。
5. 正常流量与攻击流量都必须来自同一真实入口、同一 Provider 配置和同一证据存储，不能把内部 Demo 输出混入运营指标。

### 当前仍未由论文或项目证据证明的内容

1. 任意新型提示词注入都能被识别。
2. 规则或语义分类器单独具备通用稳健性。
3. 透明代理能约束所有调用方实际执行行为。
4. 当前项目在 AgentDojo 或同等规模自适应攻击集上达到领先水平。
5. 当前中文规则在跨语言、编码混淆和多轮记忆攻击下保持稳定误报率与漏报率。

这些内容在完成公开基准、自适应攻击和正常效用评测前，不应写成产品事实。

## 产品功能决策

### 保留的唯一生产主链

```text
不可信输入或第三方数据
→ 来源与会话身份
→ 用户目标和输入风险检查
→ Provider
→ 输出与 Tool Call 二次检查
→ capability / 参数 / 数据流策略
→ 执行前闸门
→ 服务端执行或扣留
→ 执行回执
→ 请求事件与时间线
```

### 主界面只保留三项

1. 防护：实时请求流、接入应用、发送验证请求。
2. 事件：只显示拒绝、询问、隔离请求，点击后查看完整处置链。
3. 设置：应用入口、Provider、Agent 工具与数据权限。

实验室、攻击脚本、比赛报告、因果对照和 MCP JSON-RPC 调试器不进入主导航；它们可以继续作为开发与回归资产，但不能和生产数据混在同一工作流中。

## 验收指标

每次发布至少提供以下七项可复现证据：

1. 攻击成功率 ASR：最终高风险目标是否发生。
2. 正常任务成功率：没有攻击时任务是否仍能完成。
3. 误报率：正常请求被拒绝、询问或隔离的比例。
4. Provider 到达事实：请求是否真的到达真实 Provider。
5. Tool Call 泄漏率：受控调用是否仍返回给调用方。
6. 副作用事实：动作是否由服务端实际执行或在执行前被抑制。
7. 自适应攻击结果：攻击者知道现有规则后是否仍能绕过。

最低黑盒用例应覆盖：正常文本请求、直接注入、第三方数据间接注入、工具定义投毒、工具参数越权、工具结果回灌、跨会话回执、MCP 上下文隔离、Provider 故障和过期 Token。

## 主要反对意见

### “只要模型更安全，网关就多余”

模型训练可以降低风险，但论文中的 instruction hierarchy、StruQ 和 Task Shield 都没有证明任意模型、任意自适应攻击下的绝对安全。系统仍要假设模型可能犯错，并在副作用发生前执行最小权限。

### “规则加分类器已经足够”

自适应攻击研究直接反驳了这一点。规则和分类器适合排序、告警和解释，最终执行边界仍应由身份、allowlist、schema、数据流和服务端回执决定。

### “WAF 类比不准确”

这个反对意见部分成立。传统 WAF 主要处理请求特征和 Web 协议；Agent 网关还要理解会话、用户目标、Tool Call、MCP、数据流和执行事实。产品可以借用 WAF 的部署方式和实时交互，但技术边界必须明确为 Agent 运行时安全网关。
